ResolverFactory Architecture Audit

This implementation was a "behind the scenes" architectural refactor. The format of your GraphQL queries remains exactly the same.

What Changed?

Before: Monolithic

  • All resolution logic lived in schema-generator.ts.
  • One giant recursive function handled everything.
  • Impossible to unit test media resolution without the whole schema.
  • Prone to "infinite loop" bugs in complex relations.

After: Modular (Factory Pattern)

  • Logic is isolated in ResolverFactory.ts.
  • Specialized resolvers for Media, References, and Blocks.
  • Individually testable (see ResolverFactory.spec.ts).
  • Robust cycle detection with visited path tracking.

Key Accomplishments

  • Predictability: Media assets and references are now resolved using the exact same logic across the entire CMS.
  • Draft Support: We now consistently check for _draft data before falling back to published data in every field.
  • Performance: The factory caches model metadata, reducing the number of lookups needed during schema generation.
  • Safety: My audit added path-specific cycle detection, ensuring that if Object A links to Object B which links back to Object A, the system won't crash.
